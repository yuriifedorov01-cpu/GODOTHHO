## Непреложные правила

- Переноси только наблюдаемую/доказанную логику оригинала. Не придумывай новые механики, значения, состояния, UI, collision shapes, анимации, aliases, fallback или исправления «по здравому смыслу».
- Перед изменением кода составь таблицу: **точное поведение оригинала → файл/строки/ассет/измеренный runtime → соответствующий код Godot → конкретное расхождение → критерий приёмки**. Каждое утверждение должно иметь проверяемое подтверждение.
- Если оригинальное поведение или нужные данные нельзя установить, зафиксируй `НЕ УСТАНОВЛЕНО`, укажи, какой именно артефакт/наблюдение отсутствует, и не реализуй предположение. Не маскируй неизвестное заглушкой.
- Тест, проходящий на вручную заданном ожидаемом значении, доказывает только этот тест. Он не доказывает сходство с оригиналом. Не называй поведение «исправленным» без сравнения с оригиналом.
- Не меняй оригинал `D:\HHT_CLIENT`. Рабочий проект и отчёты — `D:\PERENOS_GODOT`. Пользователь просил пока сосредоточиться на анализе/подготовке, поэтому сначала проведи read-only аудит и предложи маленький следующий срез. Не начинай масштабный перенос.
- Любой отчёт, добавленный тобой, подпиши своим именем/моделью и датой. Чётко разделяй: подтверждено источником, увидено только на скриншоте, гипотеза/неизвестно.
- Не отправляй сообщения наружу, не публикуй проект и не меняй настройки компьютера.

## Текущая точка продолжения

Пользователь проверил игру вручную и прислал два скриншота. Видимы разрывы, отсутствующие и лишние тайлы, заметные границы между клетками, неверная геометрия/коллизия поверхности; пользователь также сообщает, что у мобов есть коллизия. Это пользовательские наблюдения, а точная причина и ожидаемый оригинальный результат ещё должны быть установлены.

Общий рендерер `scripts/world/TileMapRenderer.gd` уже содержит частичный порт legacy tile alias/collision geometry и fallback. Но скриншоты показывают, что это **не решило проблему полностью**. Не повторяй утверждение, будто тайлы починены глобально: общая точка применения правил есть, паритет нет. Последний записанный Stage 7 результат — 50 passed / 0 failed на картах 1, 64 и 100; он не покрывает визуальную/физическую сверку с оригиналом.

Критически важный пробел: оригинал получает серверный `tileDefs` и передаёт его в `TileDefRegistry.setPayload` (`source_analysis/decompiled_mygame/scripts/GameMain.as`, ссылки см. audit). Локально payload не найден. Не выдумывай его значения и не считай legacy rules исчерпывающими.

Для мобов есть исходное описание: оригинальный `Enemy.as` задаёт каждому врагу Rectangle для `GravityObject` и `HitTester`; в Godot найден общий круговой shape радиуса 24 у `EnemyEntity.gd`. Однако конкретная причина столкновения и точная семантика контакта ещё не подтверждены. Не отключай коллизии вслепую и не подменяй одну гипотезу другой.

Также остаётся отдельный подтверждённый аудитом вопрос HUD (`PAR-016`): часть значений и элементов в Godot похожа на фиктивные, позиции/состав отличаются от оригинала. Исправления HUD в текущем handoff не делались.

## Разрешённый ближайший шаг

Проведи компактный read-only source trace для стартовой локации и сообщений о мобах:

1. Для нескольких точно видимых скриншотных клеток проследи source map layer/cell ID → оригинальный выбор texture/atlas rect/flip → Godot cell/texture/transform. Сначала установи, какие именно клетки соответствуют дефектам; не делай массовую замену.
2. Найди все локальные места получения/хранения `tileDefs`, проверь, есть ли payload в клиенте, ресурсах, кеше или логах проекта. Если его нет, точно перечисли требуемый источник и продолжи только по правилам, которые полностью доказаны статическим оригиналом.
3. Сопоставь один конкретный тип моба: оригинальные Rectangle, `GravityObject`, `HitTester`, вызовы столкновения/атаки; затем соответствующие Godot node shapes, layer/mask и код контакта. Отдели физическое блокирование игрока от hit detection/урона.
4. Сформулируй один следующий малый фикс лишь если доказательства уже достаточны; иначе предложи способ получить недостающий эталон (например, парный runtime скрин/видео или payload). Не меняй gameplay code в этом аудиторском шаге.

Пользователь ранее просил использовать субагентов. Если они доступны и нужны, раздай им изолированные read-only вопросы и перед каждым заданием повтори запрет догадок/новой логики. Сверь их выводы с исходником сам; отчёты субагентов не считаются доказательством без ссылок на источник.

Следуй распределению трёх оставшихся моделей и условиям перехода на более лёгкую модель из `docs/MODEL_ASSIGNMENTS_AND_QUOTA_TRACKER.md`. После каждого этапа зафиксируй фактические значения usage до/после, какие модели использовались, результат и следующий этап. Не приписывай общий расход отдельной модели, если UI показывает shared pool.

Используй Context7 (`ctx7` CLI) перед любым вопросом, который зависит от актуального API Godot или другой библиотеки. Не трать Context7 на общий анализ исходной AS3 логики.
