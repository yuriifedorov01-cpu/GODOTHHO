## Обязательные правила

1. Игровую логику и ожидаемый результат брать только из оригинальных AS3/SWF, данных/ассетов оригинала или воспроизводимого оригинального runtime. Не придумывать поведение и числа.
2. Пользователь уже одобрил этот конкретный общий z-order fix — дополнительное подтверждение не требуется.
3. Менять только общий layer ordering в `scripts/world/TileMapRenderer.gd` и минимальную проверку этого инварианта, если существующая проверка не подходит. Не редактировать `D:\HHT_CLIENT`.
4. До кода проверить родительский z-index/relative z и порядок world entities. Сохранить map layers позади world entities, а FG — в том же отношении, что и original foreground.
5. Не менять opacity/alpha, IDs, alias/flip/masks, texture bounds/sampling, карты/зоны, коллизии, entities, stats, UI, воду или другие подсистемы. Не подставлять z-числа наугад; обосновать выбранные значения отношениями, установленными в original и Godot.
6. Если обнаружится, что выбранный scope не способен сохранить нужный порядок из-за структуры родителя/сцены, остановиться до затрагивания соседних систем и записать `НЕ УСТАНОВЛЕНО` с конкретным препятствием.
7. Перед запросом/использованием Godot API свериться через Context7 CLI согласно `AGENTS.md`: сначала `npx ctx7@latest library Godot "CanvasItem z_index, relative_z_index ordering in Godot 4.3"`, затем docs для выбранного ID. Уже использованные ссылки на docs не заменяют обязательную проверку CLI.
8. Не заявлять визуальный паритет на основании headless теста. Автоматическая проверка подтверждает только z-order invariant; финальная визуальная оценка — ручная проверка пользователем против оригинала.

## Критерии приёмки

- Относительный порядок map layers совпадает с original: FG > Art > Main > Water > G2 > G3.
- World entities остаются в правильном отношении к map layers после учёта parent/relative z.
- Минимальная автоматическая source-order проверка проходит; соответствующий проектный headless/launch check проходит без новых ошибок.
- В отчёте отдельно отмечено, что исчезновение всех швов/блоков этим тестом не подтверждается и ещё требует пользовательской визуальной проверки.
- Статус PAR-019 (player/enemy stats) не менялся.
