# План моделей и учёт квот — Helmet Heroes

**Владелец плана:** пользователь. **Подготовил:** GPT-6 Luna. **Дата:** 2026-11-13.

Этот файл — единая рабочая карта распределения задач между четырьмя разрешёнными моделями. Он не подтверждает качество кода сам по себе. При конфликте статусов первичны исходник/данные оригинала и свежая проверка, затем `PORT_PARITY_MATRIX.md`, затем отчёты. Чекбоксы в старых планах не являются доказательством паритета.

## Неизменные правила для всех моделей

1. Единственный источник игрового поведения — проверяемый оригинал: AS3/SWF, данные/ассеты оригинала или воспроизводимое наблюдение его runtime.
2. Никакой придуманной логики, формул, показателей, UI, collision shapes, placeholders или fallback. Неизвестное помечать `НЕ УСТАНОВЛЕНО`, перечислять недостающий источник и не реализовывать догадку.
3. До любой игровой правки представить: оригинальное доказательство → Godot-файл → точное расхождение → критерий приёмки.
4. Тест подтверждает только проверяемое условие; он не заменяет парное сравнение оригинала и Godot.
5. Каждый этап ограничен одним связанным срезом. После него записать результаты и фактический расход квоты. Не запускать повторный полный аудит, если достаточно ревью конкретного diff.
6. Оригинал `D:\HHT_CLIENT` читать без изменений; рабочие изменения только в `D:\PERENOS_GODOT`.

Подробный обязательный контракт: `ANTIGRAVITY_WORKING_RULES.md`, `TOKEN_RULES.md` и `ANTIGRAVITY_GEMINI_START_PROMPT.md`.

## Правило экономии и перехода на более лёгкую модель

- Начальная плановая доля Antigravity: до 25% на сбор доказательств, до 35% на исправления Hydrogen, до 10% на чётко специфицированную работу Flash, до 15% на интеграцию/регрессии, не менее 15% резерва. Это пределы планирования, не обещание фактического расхода.
- Основную повторяемую проверку и точечные блокирующие вопросы вести на Luna; GPT-6 Sol исключён из плана по решению пользователя.
- После каждого этапа сравнить показания до/после. Если недельный остаток Gemini падает ниже 35%, следующую низкорисковую документационную/механическую задачу отдавать Flash. Ниже 20% — прекратить необязательные агентные задачи Antigravity и дождаться сброса либо оставить только критический срез Hydrogen.
- Если Codex Go опускается ниже 25%, использовать Luna только для точечных проверок и критических блокеров. Ниже 10% — остановить широкий анализ и оставить резерв до сброса.
- Пороговые значения — внутреннее правило проекта для раннего переключения, а не лимиты платформ.

## Ближайший шаг

**Stage 5 завершён (2026-11-13), GPT-6 Luna (Codex) + 2 read-only субагента.** Проверены происхождение symbol 2970, grid atlas и сравнение sampling/placement с декомпилированным Starling. Извлечение PNG задано `source_analysis/export_swf_sprites.py`; manifest связывает `GreenAreaTiles` с ID 2970 и `1.png`, но нет FFDec version/log, source SWF hash или ожидаемого PNG hash/pixel comparison. Поэтому fidelity изображения **НЕ УСТАНОВЛЕНА**. Оригинал и Godot используют шаг/region 165 px, nearest/no smoothing и геометрию 166 px; общей причины seams этим не доказано. Для `mapMain` ID 64→52 в ячейках `(1,3)` и `(35,3)` исходник и Godot используют одинаковый atlas frame, mirror flag и cell origin. Flash задаёт vertices 0..166 и `scaleX=-1,pivotX=width`; source-to-Godot кодовый trace не доказал anchor mismatch. Возможное распределение 1 px overlap на mirror требует точного сравнения мировых bounds; это НЕ УСТАНОВЛЕНО как причина seams. Godot открывает PNG через `Image.load_from_file` → `ImageTexture`, поэтому import settings не участвуют в этом пути. Context7 CLI не удалось получить документацию (fetch failed); MCP docs подтвердили только семантику nearest, не root cause. Игровой код/ассеты не менялись; тесты и runtime не запускались. Последний quota snapshot до этапа: Codex monthly 80%, reset Dec 13; после этапа screenshot ожидается, расход неизвестен.
